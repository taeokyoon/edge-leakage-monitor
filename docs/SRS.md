## 1. 문서 규칙

- 요구사항 계층 (ASPICE 4.0): **STK** 이해관계자 요구사항(SYS.1) → **SYS** 시스템 요구사항(SYS.2) → **SWR** SW 요구사항(SWE.1).
  하위 요구사항은 상위 ID를 "근거"에 적는다 (추적성).
- 모든 요구사항은 "~해야 한다" 형식으로, 하나에 한 가지만 적는다.
- 검증 방법 (ISO 26262-6 용어 기준)
  - 테스트: 요구사항 기반 테스트. 정해진 입력을 넣고 결과를 기대값과 비교해 합격/불합격 판정 (SIL·HIL·실기기)
  - 리뷰: 문서·코드·배선을 사람이 확인
  - 분석: 지표·계산·측정 데이터로 확인 (오경보율, 지연 시간 등)
- 상태: **구현** (1~2단계 완료분) / **미구현** (3단계 이후)
- 파라미터 값은 `config/settings.yaml`을 따르며, 이 문서의 값은 현재 기본값이다.

## 7. 개요

### 7.1 시나리오 7종 (`src/leakmon/scenario.py`)

가상 설비의 누설전류·습도를 만들어 내는 "가상 플랜트 모델"이다. SIL 검증의 입력 데이터이며, 5단계에서는 같은 값을 DAC 전압으로 출력해 HIL 입력으로 쓴다.

공통 조건 (모든 시나리오)
- 시작 후 **가상 1일은 정상 운전**, 그 뒤에 이상(또는 정상 변동)이 시작된다.
- 정상 누설전류 = 4.5mA + 습도 영향(습도 1%p당 0.08mA) + 가동 시간대(08~18시) 0.4mA
- 습도는 하루 주기로 ±5%p 변한다. 측정 노이즈가 섞인다.
- 같은 시나리오·같은 seed면 노이즈까지 똑같이 재현된다.

| # | 이름 (코드) | 무슨 일이 일어나나 | 기대 결과 (요구사항) | 현재 결과 (고정 임계값 방식) | 검증 목적 |
|---|---|---|---|---|---|
| 1 | 정상 운전 (`normal`) | 이상 없음 | 경보 없음 | 경보 없음 (7일) | 오경보가 없는지 (STK-02) |
| 2 | 완만한 상승 (`gradual_rise`) | 누설전류가 하루 0.5mA씩 계속 오름 (절연 열화) | AI가 고정 임계값보다 먼저 감지 | 4일 10:00 주의 → 주의·정상 반복 → 9일 10:00 점검권고 | 조기 감지 (STK-01) |
| 3 | 습도 상승 (`humidity_rise`) | 습도가 2일에 걸쳐 +35%p 오른 뒤 유지 → 누설전류 약 +2.8mA. **고장이 아닌 정상 변동** | 경보 없음 | 2일 10:00 주의 (**오경보**) | 정상 변동과 고장 구분 (STK-02) |
| 4 | 순간 급등 1회 (`short_spike`) | 1시간 동안만 +6mA 튄 뒤 복귀 | 경보 없음, "순간 튐" 기록 | 경보 없음 (기록 기능은 미구현) | 노이즈 억제 (STK-03) |
| 5 | 반복 순간 급등 (`repeated_spike`) | 6시간마다 1시간씩 +6mA, 계속 반복 | 반복되면 주의 (기준 TBD-01) | 경보 없음 (7일, **요구사항 미충족**) | 반복 이상 감지 (SYS-07) |
| 6 | 지속적 급상승 (`sharp_rise`) | 시간당 +2mA 상승, 최대 +7mA에서 유지 | 점검권고 | 1일 03:12 주의 → 1일 07:12 점검권고 | 급한 이상 감지 (STK-01) |
| 7 | 데이터 끊김 (`data_loss`) | 3시간 동안 측정값 없음 | 센서장애 → 복구 시 이전 상태 | 1일 00:48 센서장애 → 1일 03:12 정상 | 고장과 이상 구분 (STK-06) |

- 시각은 가상 시간이며 "N일 HH:MM"은 시작(0일 00:00)부터 경과 시간이다.
- 보안 시나리오(인증 없는 장치 접속, 다른 설비 토픽에 발행)는 데이터가 아니라 통신 시험이라 4단계에서 따로 다룬다 (SYS-13).

### 7.2 용어

| 용어 | 뜻 |
|---|---|
| 누설전류 | 절연이 약해져 전선 밖으로 새는 전류. 서서히 늘면 절연 열화 의심 |
| 이상 점수 | "정상에서 얼마나 벗어났나"를 나타내는 숫자. 0이면 정상, 클수록 이상 |
| 잔차 | 실제 측정값 − AI가 예측한 정상값 |
| σ (시그마) | 표준편차. 정상일 때 값이 평소 얼마나 흔들리는지의 크기 |
| 가상 시간 / 배속 | 실제 1분에 설비 운전 1일(×1440)을 압축해 재생하는 시간 |
| seed | 난수의 시작값. 같으면 같은 노이즈가 나온다 (재현성) |
| ack | 점검 담당자가 "점검권고 확인함"을 누르는 동작 |
| MQTT | 장치↔서버가 메시지를 주고받는 가벼운 통신 규약. IoT·차량 텔레매틱스에서 많이 씀 |
| 브로커 (Mosquitto) | MQTT 메시지를 받아서 필요한 곳에 나눠주는 중계 서버 |
| 토픽 / 발행 / 구독 | 토픽 = 메시지 주소, 발행 = 보내기, 구독 = 그 주소 메시지 받기 |
| telemetry / alert / cmd | 주기 측정값 / 상태 변화 알림 / 서버→장치 명령 토픽 |
| LWT | 장치가 갑자기 끊기면 브로커가 대신 "오프라인"을 알려주는 기능 |
| TLS | 통신 암호화 (https와 같은 방식) |
| ACL | 계정별로 어느 토픽에 발행·구독할 수 있는지 정한 권한 목록 |
| WebSocket | 서버가 브라우저에 데이터를 즉시 밀어주는 연결 (새로고침 없이 갱신) |
| SQLite | 파일 하나로 동작하는 작은 데이터베이스 |
| ADC / DAC | 아날로그 전압 → 숫자 / 숫자 → 아날로그 전압 변환 칩 |
| I2C | 칩끼리 선 2개(SDA, SCL)로 통신하는 방식 |
| SIL / HIL | SW만 PC에서 가상 플랜트와 검증 / 실제 장치에 가상 플랜트 신호를 전기적으로 넣어 검증 |

### 7.3 검증 도구

- **정적분석**: 코드를 **실행하지 않고** 읽어서 문제를 찾는다.
- **동적분석(동적 테스트)**: 코드를 **실행해서** 결과를 확인한다.

| 도구 | 정적 / 동적 | 무엇을 찾나 | 자동차 업계 대응 도구 (참고) |
|---|---|---|---|
| ruff | 정적 | 코딩 규칙 위반, 버그가 생기기 쉬운 패턴, 보안 취약 패턴 (예: 문자열로 SQL 조립) | Helix QAC, Polyspace Bug Finder (MISRA 규칙 검사) |
| mypy | 정적 | 타입 불일치 (예: None일 수 있는 값을 숫자처럼 사용) | C/C++은 컴파일러·정적분석기가 담당 |
| pytest | 동적 (블랙박스) | 입력 → 기대 결과가 맞는지. 다르면 기능 결함 | VectorCAST, TESSY (단위 테스트) |
| pytest-cov | 동적 (화이트박스) | 테스트가 한 번도 실행하지 않은 코드·분기. 테스트 누락을 찾는다 | VectorCAST, TESSY (커버리지, MC/DC) |
